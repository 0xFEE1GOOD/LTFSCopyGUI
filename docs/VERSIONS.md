# LTFSCopyGui2 versions

LTFSCopyGui2 and LTFSCatalog always carry the same version, set in one place: `Common\AppVersion.vb`.
Every version pushed to GitHub adds 0.001 (1.001, 1.002, 1.003 ...) and gets a line here.

| Version | Date | Changes |
|---|---|---|
| 1.001 | 2026-11-14 | First LTFSCopyGui2 version: this branch of LTFSCopyGUI 3.6.0 with the upstream build number and the "Non-commercial License" title text removed. Includes the work on this branch so far: small-file writing, restore read-ahead, LTFSCatalog with restore hand-off, the Segoe UI facelift, and the usability changes (labelled status lights, steady I/O light, keyboard shortcut windows, menu items that open the other app). New tapes record LTFSCopyGui2 1.001 in the index creator and in the cartridge memory application name/version. |
| 1.002 | 2026-11-14 | Restore no longer stops with "Illegal characters in path". Cause: the index writer put a line break before a name that starts with ' &amp; &lt; &gt; or " (inherited from upstream LTFSCopyGUI 3.6.0; affects tapes written by it and by 1.001). The writer is fixed, and restore (folder, selected files, catalog hand-off, extract as empty files, delete disk files by index) drops line breaks at the ends of a name and replaces characters Windows rejects with _ (logged as "Name changed for Windows"). Each new index generation now records the program that wrote it (it kept the creator of the first index). |
| 1.003 | 2026-11-14 | Device configurator, TapeAlert Response log page (12h): every flag was labelled one number too low (a "Flag 00h" existed and 40h was missing), so e.g. the bit shown as "31h Diminished Native Capacity" was really 32h Lost Statistics. Labels now start at 01h, in the code and in the shipped logpages\0x12.xml. The TapeAlert log page (2Eh) was already right. |
| 1.004 | 2026-11-14 | Restore reports failures honestly. Restoring files, a folder or an LTFSCatalog request no longer ends green "Restore finished" when some files could not be restored: the light goes red and a message gives the count (the log lists the files). A read error on a small file (one that fits in one tape record, e.g. packed files) now asks Abort/Retry/Ignore like larger files instead of stopping the whole restore; Ignore skips the files of that record and asks once. A target file that is open in another program or access-denied fails only that file. "Decompress index" no longer drops the folder from the index when the archived index cannot be read back. "Move to index partition" moves only files read back whole, frees the drive and window after Cancel, and ends red when a file failed. |
| 1.005 | 2026-11-14 | "Delete disk files by index" is now "Delete disk copies of these tape files…": it asks first, deletes a disk file only when its path, size and modified time match the tape file (it used to check size only), logs every deleted and kept file, never creates folders and no longer reserves the drive. Restore names: trailing dots and spaces and Windows device names (CON, NUL, COM1, LPT1 …, also "nul.txt") are made safe ("NUL_.txt"); two tape names that become the same Windows name get "name (2).ext" instead of stopping the restore (verify and delete use the same names). A restore copies a deduplicated file from its first copy on disk instead of reading (and seeking back over) the same tape records again. Index: names are percent-decoded only when the index marks them percentencoded="true" (LTFS spec); "%25" in a plain name is no longer turned into "%" on load (folder names used to lose one "%25" per index generation); names with control characters are written percent-encoded. An index whose data placement policy or folder extended attributes hold &amp; &lt; &gt; ' " no longer fails to load, and both, with any other index part this program does not use, are written back unchanged in the next index generation (they were dropped). Block packing: no list scan per file. |
| 1.006 | 2026-11-14 | LTFSCopyGUI command bar: Force Eject now comes before Safe Eject (Safe Eject ends the bar). Main window, Other Tools: the LTFSConfigurator button had a smaller font than Index Analyzer and the others because its caption did not quite fit and it had no free space beside it; buttons side by side now share one font size (shared LTFSCopyGUI/LTFSCatalog style): when a caption in a row does not fit, the row is laid out again with each button as wide as its caption needs, and when the row is too short for that at 10 pt, all its buttons step down together (that row is 9.5 pt, evenly spaced). |
| 1.007 | 2026-11-14 | Writing: small files (under 16 KiB) are read ahead into memory again, so the drive no longer waits on the source (a NAS: one network round trip per file) for each of them. The read-ahead had stopped after a few files in every write since upstream LTFSCopyGUI 3.6.0 ("small-file preload failed: Collection was modified" in each writer log) because it walked the file list while the writer cleared finished entries from it. It now reads only files the writer has not reached yet, holds at most the configured file count and 256 MiB, and leaves any file it cannot read to the writer, which retries and reports it as before. Device configurator: closing the window while a load, eject or unthread was still running no longer logs that command as failed (it worked; only the result could not be shown in the closed window). |
| 1.008 | 2026-11-14 | Protection for a tape whose index partition is out of date. That happens when a tape leaves the drive after a write but before Safe Eject (eject button, power cut, crash): the newest index is then only at the end of the data partition, and a normal load reads the older one from the index partition. Before, a write with that older index started right after its copy on the data partition and overwrote everything written later (inherited from upstream LTFSCopyGUI 3.6.0). Now (1) after loading, the program compares the cartridge memory's volume change reference with the one recorded at the last index partition update; when they differ it says so and offers to read the newest index from the data partition (Tape > Index > Read from data partition); (2) before writing with an index loaded from the index partition, it checks that the data partition ends right after that index's copy; if more data follows, nothing is written and a message explains what to do. |
